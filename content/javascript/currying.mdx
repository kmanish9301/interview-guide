# Currying

## 📖 What is Currying?

**Currying** is a functional programming technique where a function with multiple arguments is transformed into a sequence of nested functions, each taking a single argument.

Instead of calling a function like `f(a, b, c)`, you call it like `f(a)(b)(c)`.

## 🤔 Why do we need Currying?

Currying helps in **Function Composition** and **Partial Application**.
It allows us to lock in (or "preset") certain arguments and generate a new, specialized function. This leads to extremely modular, reusable, and clean code, eliminating the need to pass the same variables repeatedly.

## ⚙️ Internal Working

Currying relies entirely on **Closures**. When the first function receives an argument and returns the second function, the second function retains access to the first argument via its lexical scope (closure), and this process repeats down the chain.

## 🧠 How JavaScript Engine Handles It

Because each returned function forms a closure, the JavaScript garbage collector will not destroy the execution contexts of the outer functions until the innermost function is finally executed and discarded.

## 📝 Syntax

```javascript
// Standard Function
function add(a, b, c) {
  return a + b + c;
}

// Curried Version
function curriedAdd(a) {
  return function (b) {
    return function (c) {
      return a + b + c;
    };
  };
}

console.log(curriedAdd(1)(2)(3)); // 6
```

## 💡 Beginner Example

Using ES6 Arrow Functions, currying becomes incredibly concise:

```javascript
const multiply = (a) => (b) => a * b;

// Partial application
const double = multiply(2);
const triple = multiply(3);

console.log(double(4)); // 8
console.log(triple(4)); // 12
```

## 🚀 Advanced Example

**A flexible Currying Utility Function:**
In interviews, you're often asked to write a wrapper function that turns _any_ standard function into a curried one.

```javascript
function curry(fn) {
  return function curried(...args) {
    // If enough arguments have been provided, execute the original function
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    } else {
      // Otherwise, return a new function that waits for the rest of the arguments
      return function (...nextArgs) {
        return curried.apply(this, args.concat(nextArgs));
      };
    }
  };
}

const sum = (a, b, c) => a + b + c;
const curriedSum = curry(sum);

console.log(curriedSum(1)(2)(3)); // 6
console.log(curriedSum(1, 2)(3)); // 6
```

## ⚛️ React Example

Currying is highly effective for event handlers in React, especially when rendering lists, to pass parameters without creating inline arrow functions on every render.

```jsx
const UserList = ({ users }) => {
  // Curried event handler
  const handleDelete = (userId) => (event) => {
    event.preventDefault();
    api.deleteUser(userId);
  };

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>
          {user.name}
          {/* No inline arrow function needed here! */}
          <button onClick={handleDelete(user.id)}>Delete</button>
        </li>
      ))}
    </ul>
  );
};
```

## ⚡ Performance

While currying is elegant, it involves creating multiple functions and closures. In high-performance, critical loops (e.g., rendering thousands of items per frame in a game), standard flat functions are faster and use less memory.

## 🧠 Memory

Because every step in a curried function chain forms a closure, memory usage is slightly higher. If a curried function retains references to large objects (like DOM nodes) and is never fully executed, it can cause memory leaks.

## ❌ Common Mistakes

Confusing **Currying** with **Partial Application**.

- _Currying_ transforms a function of `N` arguments into `N` functions of 1 argument.
- _Partial Application_ fixes a few arguments and produces another function of smaller arity (e.g., `f(a, b, c)` becomes `f(c)`).

## ✅ Best Practices

1. Use ES6 arrow functions for clean, readable curried functions (`a => b => c => a+b+c`).
2. Only curry functions when you actively need to reuse the partially applied versions.
3. Don't over-curry; deeply nested currying can confuse junior developers.

## 🆚 Comparison

| Feature        | Standard Function | Curried Function               |
| -------------- | ----------------- | ------------------------------ |
| **Invocation** | `fn(1, 2, 3)`     | `fn(1)(2)(3)`                  |
| **Arity**      | Takes N arguments | Takes 1 argument per level     |
| **Use Case**   | Single execution  | Reusable presets (Partial app) |

## ❓ Interview Questions

1. **What is the difference between Currying and Partial Application?**
   - _Answer_: Currying always returns a unary function (a function taking one argument) until all arguments are satisfied. Partial application binds some arguments and returns a function that takes the remaining arguments (can be more than one).
2. **Why do we use currying?**
   - _Answer_: To create highly reusable utility functions, avoid passing the same variables repeatedly, and facilitate function composition.

## 🔄 Follow-up Questions

**"Can you write an infinite currying function that sums an arbitrary number of arguments until invoked with no arguments?"**

- _Answer_: Yes.

```javascript
function sum(a) {
  return function (b) {
    if (b !== undefined) {
      return sum(a + b);
    }
    return a;
  };
}
console.log(sum(1)(2)(3)(4)()); // 10
```

## 💻 Coding Questions

**Write a curried function to evaluate `evaluate("sum")(4)(2)` and `evaluate("multiply")(4)(2)`.**
_Solution_:

```javascript
const evaluate = (operation) => (a) => (b) => {
  if (operation === "sum") return a + b;
  if (operation === "multiply") return a * b;
  if (operation === "divide") return a / b;
  if (operation === "subtract") return a - b;
  return null;
};
```

## 🐞 Debugging Questions

**Why does this throw an error?**

```javascript
const multiply = (a) => (b) => (c) => a * b * c;
console.log(multiply(2, 3)(4));
```

_Fix_: Curried functions expect exactly one argument per invocation level. `multiply(2, 3)` passes two arguments to the first function (the `3` is ignored), returning the second function. But we didn't invoke the third level. It should be `multiply(2)(3)(4)`.

## 📄 Cheat Sheet

- **Currying**: `f(a, b)` -> `f(a)(b)`
- **Mechanism**: Closures remember the outer arguments.
- **Benefit**: Reusability, Partial Application, modular code.

## ⚡ 2-Minute Revision

Currying breaks down a function taking multiple arguments into a chain of functions taking one argument each. It leverages closures to remember variables. It's heavily used in Functional Programming and Redux middleware.
